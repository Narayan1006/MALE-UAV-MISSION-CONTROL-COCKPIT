## System Overview

AeroTwin is designed as a **plug-and-play health monitoring add-on** for existing
long-endurance fixed-wing UAV platforms. The system adds a sensor harness,
edge compute node, and RF telemetry link without modifying the primary flight
control system.

```
[Aircraft Engine]
       |  Sensor harness (K-type thermocouples, pressure transducers)
       v
[Raspberry Pi 4 — Edge Node]
  - Runs lightweight Isolation Forest anomaly detection (< 100 ms)
  - Buffers telemetry, applies Data Quality Guard
  - Packs into MAVLink v2 frames (custom message ID 50001)
       |  RFD900x 900 MHz radio link (up to 40 km LOS)
       v
[Ground Station Laptop]
  - Runs full AeroTwin FastAPI stack
  - Full XGBoost fault classification + RUL regression
  - TreeSHAP explainability
  - AeroTwin Flight Deck dashboard (browser)
```

## What Requires Real Hardware to Validate

We explicitly acknowledge the following claims **cannot** be verified without
physical hardware. This is not a weakness — it is a honest scoping boundary
appropriate for a software prototype.

| Claim | Why Real Hardware Is Needed |
|-------|-----------------------------|
| **Sensor accuracy at temperature extremes** | K-type thermocouples exhibit ±2°C typical error; real CHT/EGT under combustion involves EMI, thermal mass lag, and vibration coupling not modelled here. |
| **Pi 4 inference under throttling** | Thermal throttling at sustained load reduces Cortex-A72 clock from 1.8 GHz → ~1.0 GHz. The 4× correction factor is empirical; real figure depends on ambient temperature and case design. |
| **RF link at range and under multipath** | Gaussian latency model is idealized; real 900 MHz propagation includes terrain diffraction, vegetation loss, and Fresnel zone effects. |
| **CAN bus / ECU integration** | Our simulator produces the same 14-channel telemetry as a real engine ECU would; the MAVLink framing is ready, but actual ECU serial protocol (e.g., Rotax 912 iS CAN) requires hardware access and NDA-covered documentation. |
| **Vibration isolation and EMI hardening** | Raspberry Pi 4 is not aviation-certified. A real deployment would require conformal coating, vibration-damped mounting, and EMI shielding validation in an avionics enclosure. |
| **RUL prediction accuracy on real engine wear** | Our RUL model is trained on simulated degradation trajectories. Real engine wear involves metallurgical mechanisms (micro-cracking, oil viscosity breakdown, carbon fouling) that our physics model approximates but cannot fully reproduce. |

## End-to-End Round-Trip Latency (Simulated)

The full chain: **Sensor → MAVLink Pack → RF Link → Edge Infer → Ground Unpack**

Run the pipeline test:
```bash
python backend/pipeline_test.py
```

Expected output on a modern laptop:
```
MAVLink pack:        ~0.05 ms
RF transmit (sim):   ~50 ms  (mean, incl. Gaussian jitter)
MAVLink parse:       ~0.04 ms
Edge inference:      ~0.5–2 ms  (host); ~2–8 ms estimated Pi 4
                    ─────────────────────────────────────────
Total round-trip:    ~51–52 ms  [SIMULATED]
```

The 50 ms link latency dominates — which matches real RFD900x operation.
Reducing this requires higher air packet rate (reduced range) or ground-side
inference offload (current architecture).

## Cost & Impact

**The Math.** The AeroTwin hardware add-on costs an estimated $833–$1,007 (BOM above). Typical commercial long-endurance piston/gas fixed-wing UAV platforms span a typical commercial platform value range of $12,000–$100,000+. | **Fault Awareness** | Warning light at failure onset | Predictive alert minutes before onset |
| **Action Time** | Seconds to react | Minutes to execute planned diversion |
| **Outcome** | High risk of forced landing / hull loss | Controlled precautionary landing |
| **Hardware Cost** | $0 | $833 – $1,007 |
